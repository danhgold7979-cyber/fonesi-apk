# Owned-fixture boundary tests — design only, NOT RUN

Input: independently authored owned fixture packages and synthetic per-instance secrets; generated test-only signing keys retained locally, never customer/session material. SDK execution only in an already authorized environment, and provider execution only after source/license/boundary review. No third-party app binaries/accounts in the first gate. No fixture or engine is built/executed by this document.

Each receipt binds manager/provider/fixture source SHA, artifact and dependency digests, declared versus measured principals, Android/API/ABI/page size/OEM, operation ID/generation, complete scope, before/after readback, command/result, and redacted diagnostics. Record HOST, COMPILE, ANDROID, PROVIDER, PHONE separately; never infer a higher tier. Source/oracle code from the previous implementation remains archive-only; all fixture/test logic will be independently authored.

## What lower tiers cannot establish

HOST can falsify malformed inputs, bad transitions or unsafe decisions on synthetic data; it cannot establish actual Android UID/SELinux isolation, Binder ownership, arbitrary native-code containment, framework scheduling, guest lifecycle, authentic provider readback, OEM data transfer, login/notification or app compatibility. COMPILE can establish packaged API/resource/manifest/signature facts but cannot establish that Activity/service/provider callbacks ran or user data survived. ANDROID fixture execution still does not prove an eligible production provider or eight third-party apps. PROVIDER synthetic results still require exact physical/OEM/account acceptance.

Stop immediately on cross-instance/original access, identity substitution, unknown scope, untrusted telemetry, missing binary provenance, stale authorization, unexplained crash suppression or lost data. Preserve synthetic evidence locally, never retry mutation merely because a timeout occurred. Correct the cause and rerun affected cases; independent review is required before changing eligibility. Failed or unknown results are useful findings, not completion.
