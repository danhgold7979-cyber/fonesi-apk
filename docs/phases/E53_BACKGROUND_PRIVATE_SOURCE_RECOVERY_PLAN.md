## Safety defect and dependency

Foreground `UpdateRunner.recoverLocked` (E48/E52) fails closed for retained private APK tasks and legacy E41 UPDATE_TASK/REVIEW_REQUIRED owner references. The headless `UpdateJournalRecovery` used by `UpdateJournalRecoveryWorker` still unconditionally discards snapshot data and rewrites every PREPARING task to QUEUED. Because WorkManager runs even when the app UI is closed, private retained snapshots may be discarded and their journal state silently reset. A stored source must not be mistaken for an original app APK simply because its task uses the old pre-marker schema.

## Implementation and test sequence

1. Reconfirm E52 exact SHA and CI, read E48's retained-source guard, `UpdateJournalRecovery`, worker, `RoomLegacyUpdateSourcePolicy` and current JVM/Robolectric/native SQLite tests; leave E51/E52 branches and main unchanged.
2. Add a narrow, pure callback to `UpdateJournalRecovery`: `allowPreparingCleanup: (UpdateTask) -> Boolean`, placed **before** existing trailing `clock` argument for Kotlin compatibility. Default fail closed for tasks with `retainedSource`; add an explicit unconditional retained-marker gate before calling any external callback. A false callback result deliberately **holds** PREPARING and its snapshot untouched, rather than forcing worker retry or unverified success.
3. Wire production `UpdateJournalRecoveryWorker.recoverJournal` with existing read-only `RoomLegacyUpdateSourcePolicy(database)::allows` to reject both retained flags and pre-marker E41 UPDATE_TASK/REVIEW_REQUIRED cluster owners before snapshot IO. If the authority read fails/throws, leave journal+snapshot unchanged and return retryable; preserve sanitized WorkManager output and no runtime/guest dependency.
4. Preserve normal legacy PREPARING behavior and existing APPLYING/VERIFYING -> REVIEW_REQUIRED without snapshot deletion, including retained private tasks (unknown outcome must be retained, never succeeded or rerun). Do not change Room schema, queue lock/pause and source provider.
