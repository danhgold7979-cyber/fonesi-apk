## Residual hazard

`ManagedGuestEngine.create` checks `checkCreatePeers` before reserving an ID, but then creates the native user and immediately calls `backend.install`. Another guest in this shared-package engine could start running, change version/signers or leave registry, or a new RESERVED peer could appear **after** the previous peer check. The SDK import might replace shared package code while existing accounts are using it. Also the frozen snapshot could change or an unexpected guest package could appear under the just-reserved native user between initial SDK preflight and install. Existing E63/E66 guards do not cover this create-user window.

## Ordered code/test/CI plan

1. Commit this detailed plan and EXECUTION_PLAN entry **before** editing production code. Preserve E65/E66 behavior, review parent CI and HEAD.
2. Immediately before registry reservation, save a full same-package `GuestInstance` identity snapshot (IDs/native users/states/pending) following the existing valid peer preflight. After `backend.createUser` and native user confirmation, but before `backend.install`, repeat `snapshots.verify(snapshot)`, ensure the just-reserved row has unchanged identity and its SDK package is still absent, require all *other* same-package guest rows exactly match the prior snapshot and are READY, and read their guest package identities again to ensure exact source version/signers and `running=false`. Abort SDK install on any mismatch.
3. Any exception **after** the first native mutation leaves the reservation and snapshot durable for explicit reconciliation; no uninstall/rollback, reuse of user IDs, or fallback to original app. Do not newly demand foreground authorization after native mutation, because E65-era create flow explicitly completes safe readback even if authorization expires following native user creation.
4. Add focused JVM backend-double interleaving regressions: native peer starts running after user creation, peer signers drift, a peer disappears or new RESERVED peer appears, the frozen snapshot fails re-verify, and an unexpected native package appears under the reserved user. Assert no additional SDK install/no native uninstall, reservation remains RESERVED and snapshot is kept; keep existing positive multi-clone creation and early-authorization-loss tests.
5. Add `scripts/audit_e67_create_preinstall_peer_guard.py` and exact-source pinned E40–E67 cloud/candidate workflow. Require tests/build/lint, signed APK permissions, no split/provider/GC activation and source-SHA check before technical PASS; no waived assertions or synthetic success.
6. Record exact source SHA/CI/test totals in E67 results and STATUS/EXECUTION_PLAN/PRODUCT_PROGRESS; a follow-up reporting SHA requires its own CI. Draft stacked PR against E66; leave `main` untouched.
