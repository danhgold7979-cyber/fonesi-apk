## Current gap

E68–E72 can cryptographically audit PRIVATE base/split manifest data, bind its inventory to a `GuestCodeLoader` image, and select an explicit signed Activity or alias with conservative exported/enabled/process/permission rules. The returned `VerifiedPrivateActivitySelection` is still only a string target. The host/source runtime does not verify that a class of that name actually exists in the PRIVATE DexClassLoader, is a concrete Android Activity, or was **defined by** the private loader rather than delegated to the host/framework parent. Future guest lifecycle routing must never use a host `Class.forName` or fall back to an installed original app.
