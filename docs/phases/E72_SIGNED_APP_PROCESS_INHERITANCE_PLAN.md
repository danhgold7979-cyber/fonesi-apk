## Specific gap and scope

E71 rejects an explicit per-Activity/alias `android:process` on a signed PRIVATE `VerifiedPrivateComponentInventory` selection. But Android also permits a base `<application android:process>` default inherited by Activities that omit their own process. E68 `PrivateApkComponentCatalog` currently reads the base application's class, permission and enabled fields but **drops the application process declaration**; E70/E71 then return a selection even when the signed application declares an unmediated process. Feature/config splits must not redefine Application process ownership. The Fonesi source guest runtime still lacks a native Android guest process allocator, framework/Binder lifecycle and independent UID/account acceptance.

## Ordered implementation and gates

1. Commit this detailed plan and an E72 section in `docs/EXECUTION_PLAN.md` **before production code**. Read exact E70/E71 source and PR/CI, preserve existing signed identity, permission, enabled, exported and alias checks.
2. Extend `VerifiedPrivateComponentInventory` with an optional `applicationProcessName`, taken only from the signed PRIVATE base binary manifest through the bounded `android:process` string parser. Preserve null for undeclared process; reject nonbase feature/config manifests that attempt to redefine the Application process, like existing Application permission/enabled policy. Keep base/split signature and hash re-open checks.
3. `SignedPrivateExplicitActivityResolver.select` must require `inventory.applicationProcessName == null` for **both** `TRUSTED_INTERNAL` and `EXTERNAL_UNTRUSTED`, before returning the selection, in addition to E71's requested and resolved component process guard. Do not interpret null as an accepted Android runtime process mapping, only as absence of a signed override. Do not create `Intent`, launch an Activity, register a host proxy, or weaken permissions.
