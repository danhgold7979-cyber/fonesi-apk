## Threat-model decisions

1. A clone ID, label, engine user number, or separate UI tile is not proof of account isolation. Acceptance requires adversarial reads across each clone's private files, preferences, databases, URI grants, notifications and process state at the provider's actual boundary.
2. Copying split APK files or deriving split names from filenames is not equivalent to installing a verified cluster. The provider must preserve split dependency/configuration metadata, signer/version identity, resources, native ABI and readback across restart.
3. Suppressing crashes, hiding device identity, spoofing environment properties or sending diagnostics externally is not an acceptable substitute for compatibility. Any candidate with these paths needs explicit review and a clean configuration before testing.
4. Root repository license does not automatically license bundled native archives, SDK AARs, injected frameworks or transitive dependencies.
5. A synthetic host Activity/View dispatch proof validates the test harness only; it cannot qualify a provider for arbitrary third-party guest lifecycle.
