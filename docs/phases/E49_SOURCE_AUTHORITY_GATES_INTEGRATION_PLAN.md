## Original product alignment and risk

**Phase 4, roadmap steps 17–20**, under the existing eight-product-phase roadmap. E46 protects foreground automation from cancelling/retrying private retained work using the installed original app; E47 blocks manual confirmation of a conflicting original-app queue while a private retained task exists; E48 guards interrupted/private recovery from claiming success via legacy engine readback. Individually they protect different boundaries of one durable update pipeline. Integrating their code and tests makes sure they coexist without altering the original update route or losing private source ownership.

## Acceptance and rollback conditions

Any of three gates missing is a failure. Retained private-source marker/Room owner must never be reinterpreted as an original-app source, cancelled/retried by legacy foreground automation, enqueued through manual original consent during a conflict, or marked successful through a legacy engine after process interruption. Existing unassociated legacy tasks must still work; source-control and file provenance remain unchanged.
