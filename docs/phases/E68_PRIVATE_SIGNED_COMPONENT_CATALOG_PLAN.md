## Verified gap and scope

The existing `PrivateSyntheticComponentCatalog` in opt-in `engine-source` reads only one hardcoded signed project-owned APK in a dedicated probe. `ApkSetAuditor` and `PrivateApkStore` already verify cryptographically signed private base/feature/config APK sets, but do not return a generic per-component manifest inventory. No supported path exposes real third-party app/split component names/permissions/process/exported metadata from signed PRIVATE paths without calling installed original-app PackageManager. A separate manifest-only data component is a necessary input to a future provider, **not an Activity/Service/Provider registration or launcher**.
