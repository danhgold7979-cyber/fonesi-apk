## Gap and bounded target

E73 adds an opt-in `LoadedGuestCode.preflightExplicitActivityClass` API to prove a signed Activity has matching class name/type and PRIVATE defining classloader on Android, but its JVM-only tests cannot prove that the Android synthetic probe calls this API with an actually signed private APK and real DEX. The existing E24/E29 `SyntheticGuestUiProbeActivity` already loads independently signed project-owned `vn.fonesi.payload` classes into a dedicated host process and renders a PRIVATE View. A *distinct* opt-in mode is needed to check `vn.fonesi.payload.PayloadActivity` is a signed declared Activity class loaded from the same signed PRIVATE image, without attaching it to the host ActivityThread.
