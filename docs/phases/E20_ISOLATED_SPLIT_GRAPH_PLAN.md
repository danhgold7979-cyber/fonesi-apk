## Implement narrow, testable source component

1. Add pure `engine-source/GuestSplitGraph.kt`: given an existing cryptographically verified `GuestCodeLayout`, derive a deterministic per-classloader graph:
   - one base node with its base configuration APKs;
   - one node per feature split, including only its matching configuration splits;
   - every feature node's parent is base or its single explicit verified `uses-split` feature dependency.
2. Determine topological order, detect missing/ambiguous/multi-parent dependencies, cycles, configuration without target, duplicated membership and complete path coverage. Respect verified split identity rather than filenames. Never use original installed app resources as a fallback.
3. Reject cases that require multiple feature parents not representable by Android `ClassLoader.parent` in this implementation. Preserve source APK ordering and full cluster byte integrity.
4. Test against real signed APK fixtures already generated by pinned SDK/apksig, including `isolated-base`, `base`, `dependent-feature`, `chat-config`, `base-config`. Verify stable graph regardless input order, correct parents, no silent flatten, no APK omissions, and non-isolated cases remain a separate explicitly flat plan. Retain E9 `GuestCodeLoader` isolated-split refusal.
5. Run source Kotlin/JVM tests, signed APK fixture generation, ARM64 source AAR compile/lint on pinned toolchain. Log commands/test counts and fail on test or build error. Do not claim actual isolated DEX/resources executed on Android from graph tests alone.
6. Next required slice: dedicated Android isolated split classloader/resource implementation and a signed synthetic feature resource/code runtime test before allowing provider use. Explicitly leave E20 as `JVM_GRAPH_ONLY` until those are implemented and proven.
