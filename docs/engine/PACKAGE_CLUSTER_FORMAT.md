# Fonesi Verified Package Cluster Format — E35 draft

Status: specification only. This is the proposed immutable source representation; it does not enable split APK import in the current provider.

## 1. Envelope

A `VerifiedPackageCluster` is immutable and content-addressed. The envelope contains:

- `schemaVersion`: integer, currently proposed as `1`;
- `clusterId`: UUID generated by Fonesi after successful validation;
- `sourceGeneration`: monotonic generation/UUID for the original installed app snapshot;
- `packageName`: canonical Android package identifier;
- `longVersionCode` and `versionName` when present;
- `signerSha256`: sorted set of SHA-256 digests of APK content signers; signing lineage, when available, is stored separately and never inferred from the current signer set;
- `members`: exactly one base member plus zero or more split members;
- `splitDependencyGraph`: explicit graph of split dependencies from validated metadata;
- `manifestDigest`, `auditPolicyVersion`, `auditedAtEpochMs`;
- `providerCompatibilityResult`: provider ID/revision, supported capability snapshot digest, and explicit PASS/FAIL/UNKNOWN status;
- `clusterDigest`: SHA-256 over canonical serialized metadata plus ordered member hashes.

No caller-supplied `clusterDigest` is trusted; it is recomputed after validation.

## 2. Member record

Each member records:

- `role`: `BASE`, `FEATURE_SPLIT`, `CONFIG_SPLIT`, or `UNKNOWN` (UNKNOWN is rejected for execution);
- `splitName`: null only for BASE;
- `configForSplit`, `usesSplits` and validated dependency names where applicable;
- `targeting`: ABI, density, language and other configuration targeting parsed from trusted APK metadata;
- `canonicalStagingPath`: private staging path only; never accepted from an external caller;
- `byteLength`, `sha256`, `packageName`, `longVersionCode`, signer digest set;
- `zipIntegrityStatus`, `manifestParseStatus`, `nativeLibraries` with ABI/ELF metadata;
- `publishGeneration` and immutable store object ID.

## 3. Validation invariants

- Exactly one BASE member exists.
- Every member has the same package name, long version code and compatible signer identity as the cluster envelope.
- Split names are unique; dependencies reference present members and form a valid graph with no missing nodes or cycles where the platform format forbids them.
- Every member's SHA-256 and byte length are recomputed from the exact bytes that will be published.
- The source files remain stable while hashing; if source generation changes during capture, abort and restart snapshotting.
- Paths are canonicalized and checked against an approved root; symlinks, `..`, non-regular files and paths escaping the root are rejected.
- APK members are not merged, re-signed, renamed to disguise identity, or selected by filename/size heuristics.
- Required ABI/config splits must be selected by validated metadata for the actual device/provider capability, not merely the largest APK or first filename.
- A complete cluster is published atomically; readers never see a partial generation.
- Readback after publish rechecks every member hash and envelope digest.

## 4. Storage layout (logical, not yet implemented)

`files/package-clusters/<package-hash>/<clusterId>/manifest.json`

`files/package-clusters/<package-hash>/<clusterId>/base.apk`

`files/package-clusters/<package-hash>/<clusterId>/splits/<splitName>.apk`

The package hash is derived from the canonical package name, not supplied by the caller. Directory creation uses private app storage and no external storage. The directory is marked immutable after publish. Garbage collection may remove a generation only when no clone instance, update task, review-required journal row or rollback reference points to it.

## 5. Canonical serialization

- UTF-8 JSON with fixed field ordering or an explicitly canonical JSON implementation.
- Lowercase hexadecimal SHA-256 strings, no prefixes or whitespace.
- Sorted signer digest sets and sorted map keys; member ordering is deterministic: BASE first, then split names in lexical order for the envelope, while execution order follows the validated dependency graph.
- Reject unknown fields for schema v1 in signed or security-sensitive receipts unless an explicit forward-compatible extension namespace is defined.
- Schema upgrades are versioned migrations; older readers fail closed when required semantics are unknown.

## 6. Provider boundary

The cluster format is source identity and storage metadata, not proof of installation or execution. The provider must return an independent post-install readback receipt with actual guest package/version/signer/component state. A source cluster cannot be marked `INSTALLED` just because its files exist in private storage.

## 7. Current status

This format is proposed, not implemented. The current SpaceCore candidate still requires a single APK and `supportsSplits=false`. No product code may set split support based only on this document.
