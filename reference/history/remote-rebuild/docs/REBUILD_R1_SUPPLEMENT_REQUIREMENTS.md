## Decisions and non-substitutions requiring explicit review

1. Historical S1 AndroidX versions, FragmentActivity and cloud/candidate layout were an old implementation recipe. Their normative result is supported system authentication and exact dependency/manifest compatibility. A fresh implementation must review current official compatibility before choosing dependencies; this ledger neither installs them nor silently makes them acceptance requirements for the dependency-free reader.
2. EXEC-ID-R1-01 in REBUILD_R1_DECISIONS.md now records root's constraints: exact opaque CatalogKey stays display-only; synthetic UUIDs are internal references, not converted legacy IDs. Future current receipts must bind exact key, verified provider/revision/environment, actual handle/generation and authorized scope with independent access/foreground checks. Unknown bindings stay quarantined. The provider mapping format remains BLOCKED / NOT IMPLEMENTED until provider selection and review; SUP-U23 is not fulfilled.
3. Configuration label/group/style limits are normative for those future formats/editors, not a reason to reject or rewrite historical catalog opaque IDs. Current reader budgets are separate resource limits with quarantine, not a new schema grammar.
4. STYLE-R1-01 in REBUILD_R1_DECISIONS.md explicitly resolves the broad path/signature prose as a closed typed schema and inert plain glyph rendering.
