## Acceptance profiles used by the atomic PLAN rows

Each row supplies its own positive result, negative case and race/recovery case. The profile adds these universal stop conditions without relaxing the row:

- **DOC:** check retained scope against the pinned source; contradictory or missing claims stop documentary closure. No runtime inference from prose.
- **MAN:** host state tests then real native UI/lifecycle/launcher evidence. Stale owner/token, failed auth, unknown provider or missing row must not mutate/open a guest. Stop on wrong identity or misleading success.
- **ENG:** reviewed source/license/environment plus synthetic hostile-guest tests before third-party accounts. Stop on missing provider, unverified isolation, leakage, fake lifecycle or unsupported capabilities. No original-app/web fallback.
- **UPD:** synthetic source/queue tests then actual provider and phone update/readback. Stop on source drift, missing authority/consent, running/unknown peer, uncertain journal, incorrect version or data loss. Retain/quarantine, never blind replay or downgrade-as-rollback.
- **DATA:** synthetic transaction/migration then Android file/SQLite/SAF tests. Stop on unknown ownership, malformed input, partial write or identity ambiguity; retain originals, no silent remap/drop/delete.
- **REL:** measured physical configuration and signed upgrade/release evidence. Stop on missing required apps/device tests, known loss/mixing, unsupported release claims or unauthorized publication.
