## Primary-source behavioral findings

1. AOSP Android8.0 header pins SQLite **3.18.2**. index_xinfo was introduced3.8.9, so baselineAPI26 has it. table_xinfo arrived3.26 and is excluded, as are table_list/sqlite_schema/window functions. Require actual expected PRAGMA columns/rows; an empty/unsupported result fails source, never falls back to weaker validation. [AOSP header](https://raw.githubusercontent.com/aosp-mirror/platform_external_sqlite/android-8.0.0_r1/dist/sqlite3.h), [3.8.9 release](https://www.sqlite.org/releaselog/3_8_9.html), [3.26 release](https://www.sqlite.org/releaselog/3_26_0.html).
2. AOSP open() invokes onCorruption then retries openInner if the handler returns. Therefore nondeleting handler must throw, not merely log/no-op. The outer open failure closes resources. Default error handler is unsuitable. [AOSP SQLiteDatabase](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-8.0.0_r1/core/java/android/database/sqlite/SQLiteDatabase.java).
3. SQLiteCursor refills windows by calling SQLiteQuery.fillWindow again, which executes via its session. Do not assume a cursor pins a whole logical page snapshot. Validate joined catalog_id/revision on every row, **close page cursor**, then make a fresh independent metadata read; compare again before publication. [SQLiteCursor](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-8.0.0_r1/core/java/android/database/sqlite/SQLiteCursor.java), [SQLiteQuery](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-8.0.0_r1/core/java/android/database/sqlite/SQLiteQuery.java).
4. NO_LOCALIZED_COLLATORS bypasses locale-table handling in the baseline connection implementation; use it on both initialization and reads. [SQLiteConnection](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-8.0.0_r1/core/java/android/database/sqlite/SQLiteConnection.java). These source findings are not an assertion that every OEM behaves identically.

## Exclusive bootstrap and existing-file open recipe

All steps run off main thread, with application Context only. Reject device-protected/locked storage; derive fixed `manager-catalog-v1.sqlite` under trusted no-backup parent. Check canonical parent and lstat directory/UID; no external/custom path input. Check file lstat if present, rejecting symlink/nonregular/wrongUID/insecure write permissions. Record dev/inode, recheck around open and before successful return. Same-UID hostile file replacement is outside this trusted-root design; no guest shares this boundary.

Call createNewFile once: true grants only this invocation initialization permission; false means existing validation-only path. If a competing creator's partial file is observed, fail retained—do not spin/retry/delete/initialize it. If creation throws, outcome is uncertain and no initialize attempt follows. Creator validates new regular file/owner before open. Use READWRITE + NO_LOCALIZED_COLLATORS without CREATE_IF_NECESSARY for the already-created empty file; pin new-file DELETE journal mode/FULL synchronization, encodingUTF8, then transactionally execute exact DDL, application_id1178815793,user_version1 and singleton insert. Close creator connection and reopen READONLY for verification/read. No provider dispatch follows any outcome.

Existing path: READONLY + NO_LOCALIZED_COLLATORS + throwing nondeleting handler. Never reopen readwrite for recovery, enable WAL, upgrade, VACUUM, repair or recreate. Unknown version/schema, zero/partial/corrupt file, unexpected sidecar/recovery requirement or unsupported read-only behavior fails and retains files. File birth/close/SQLite commit behavior still requires later Android runtime tests; source audit does not prove power-loss durability.

## Query recipe and result contract

See `REBUILD_CATALOG_QUERY_RECIPE.md` for the fully expanded candidate SQL. It uses only SELECT/CASE/typeof/length/CAST/subquery/LEFTJOIN/ORDERBY/LIMIT primitives available in baselineSQLite3.18.2, no extensions. This is a reviewed recipe, **not executed Android SQL evidence**.

First page uses rowid>=Long.MIN_VALUE; next page uses rowid>lastAcceptedRowid. Two fixed query constants differ only by this operator; bound decimal numeric cursor, never interpolated user SQL. Do not use `first OR rowid>cursor`, which could defeat index positioning. Rowid is pagination position, not CatalogKey. Return at most129 rows with a metadata-only sentinel for an empty window. Preserve type/NULL/length/overbudget flags independently from BLOB data, including catalog_id. Readiness and launch_allowed become strict inert-state integer validation flags, not display text parsed as authority.

Every row must have identical strictly decoded catalog_id and integer nonnegative revision; match requested cursor binding. Any unexpected cursor exception/refill/type/ordering outcome fails the whole page. Verify strictly increasing positions, exact duplicate keys absent, bounds and cancellation at each step. Close page cursor before final metadata query; require same catalog_id/revision then check deadline/cancellation/loader owner and main-thread RefreshTicket before publish. A later page at a different revision fails with restart-required. No partial publication, stale-snapshot merging, row skipping or empty-success from failure.

This is a consistency contract under future trusted writers atomically bumping monotonic revision with every data change, without wrap/reset. It is not hostile-file tamper proof. A write after final read can make a valid snapshot stale; selection remains display-only, never mutation authority.

## Main-thread delivery and bounds

One application-owned worker survives Activity recreation; at most one active and one replaceable pending request. Do not create a worker per resume or use unbounded executor queues. Replacement cancels prior request and removes its queued work; rejection becomes a visible current-ticket failure, never execution on caller/UI thread. All Cursor/database ownership stays on worker.

Handler is explicitly bound to mainLooper. Completion captures controller+RefreshTicket+immutable result, not an Activity reference in the worker. Pause cancels request and detaches controller; view is cleared before late publication. Main runnable rechecks loader ownership/deadline/cancel and controller's existing pending-ticket identity/epoch; only then publish/fail. Timeout failure cannot later be reversed into success. Post failure also invalidates result; no callbacks grant provider authority.

Approved128row/256KiB aggregate/16KiBfield/4096UTF16 and normalized8192UTF16 limits remain read/render budgets, not schema validity. SQL bounds transferred BLOB cells; strict decoding preserves exact key bytes/codepoints. GroupNULL alone maps to empty display without updating storage. Native CursorWindow/open/locking overhead and cancellation latency are not a hard heap/deadline guarantee. No runtime source other than this owned empty catalog is introduced.
