### Ordered bridge acceptance, not implementation authorization

1. **Logical contract bridge:** extract/port the kernel's capability/identity/state logic to a separately tested API26-compatible source boundary, keeping the host oracle and all negative tests. Freeze golden identity equality, provider/environment/cluster/peer binding, deterministic codec v2 bytes and scope hashes. Include UUIDs with high bits set (UUID.compareTo ordering), supplementary Unicode provider IDs, and malformed-surrogate handling. Preserve existing UTF-16 String.length framing and UTF-8 hashing semantics, or explicitly version/quarantine incompatible identities; visually similar text is not byte equivalence. Fail unknown versions; never silently reinterpret v1/unbound records. No provider capability is created by compiling this bridge.
2. **Ownership boundary:** obtain manager-private, credential-protected/no-backup storage from trusted application context; never accept a guest/external path, UI display string or configuration import as authority. Establish directory ownership/permissions and process trust. A same-UID hostile guest invalidates the trusted-root assumption; UI token owner identity is not OS isolation/authentication. Persist complete provider revision/package/environment/scope/UUID/peer identity. Preserve historical owners; unknown ownership stays quarantined and never releases/deletes guest data.
3. **Durability adapter:** API26 has NIO file APIs, but runtime `fileKey`, NOFOLLOW behavior, directory-open/fsync, atomic rename and cross-process file-lock semantics still require Android/OEM tests. Define a storage interface retaining CREATE/CAS/no-replay semantics; choose a proven Android file adapter or separately proven SQLite transaction adapter, not a silent fallback. Keep force-before-rename/parent durability, uncertain commit => no dispatch, reopen diagnosis only, and every conflicting operation under the same provider-package lease. Linux tests are not portable filesystem proof.
4. **Dispatch/auth bridge:** actual authentication + foreground lifecycle is a separate trusted input, not `Render.active` or a selected row. Freeze signed base/split source and complete peer consent; revalidate before dispatch/readback. Connect only reviewed provider implementations with independent private readback. Persist DISPATCHED before any external mutation; unknown outcome remains REVIEW_REQUIRED. Main-thread UI receives immutable status after trusted work is marshaled safely; never execute filesystem/provider work in a rendering callback.
5. **Acceptance:** source/API lint + D8, host parity tests, then controlled Android API26/current runtime tests for lifecycle/crash/locking/fsync/CAS and independent readback. Real provider/hostile-guest/device matrix is a subsequent external gate. No emulator, SDK install/license acceptance, device action or provider choice performed by this audit.

Old implementation deletion still waits corresponding tested replacement. This bridge plan does not turn metadata presentation into authorization, a storage migration or engine completion.
